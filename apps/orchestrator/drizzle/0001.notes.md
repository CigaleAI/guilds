# Drizzle `0001` baseline

`0001_baseline.sql` is a schema-only snapshot of core's DDL. A new
install applies it, then later numbered files.

It is applied as custom SQL (not `drizzle-kit push`). Regenerating the
file: apply this migration to an empty `postgres:17` database, dump with
`pg_dump --schema-only --no-owner --no-privileges`, and run
`apps/orchestrator/scripts/dump-baseline-schema.ts`.

Intended properties:

1. **No migration-metadata tables besides `__drizzle_migrations`.**
   Scripts live in `artifacts` (`kind` `script`); collections live in
   `artifact_collections` / `artifacts`.
2. **No data backfills.** Catalog rows and native-tool bindings are
   owned by `src/db/seed/`.
3. **`__drizzle_migrations` is present** after migrate, in schema
   `public`. Compare dumps after stripping that table.
4. **`artifacts.search_document`** indexes `note` and `memory` only.
   The standing task lives on `agents.task`.
5. **Session GUCs in `pg_dump` are not schema.** The dump keeps
   `default_tablespace` and `default_table_access_method` the way
   PostgreSQL emits them; other `SET` lines are dropped.

`drizzle-kit generate` is not the source of `0001`. The optional
`test/integration/schema-diff.test.ts` compares a boot migration against
applying the numbered SQL files directly.
